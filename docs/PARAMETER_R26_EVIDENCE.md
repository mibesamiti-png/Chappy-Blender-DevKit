Internal reducer cbdk/parameter_fixture_evidence.py follows R25's fail-closed identity and bounded vocabulary principles and reuses its exact Blender version allowlist. No public CLI, execution API, source change, property recommendation or shared runner change.

## A integration contract

Call reduce_parameter_evidence(static, native, case=..., blender=..., run_id=..., source_sha256=...) with the independently expected parent identity, not values inferred from either input. case is parameter_fixture_r26; blender is exactly 4.4.3, 4.5.15, or 5.2.1; run_id is a fresh lowercase 32-hex token from the trusted parent; source_sha256 is the actual fixed source bytes' lowercase 64-hex digest. Each input envelope repeats these four fields, plus properties (a list, each fixed property once). Native additionally has cleanup_verified and source_unchanged, both actual booleans. Static row fields exactly property, declaration_count, same_class_self_count, geometry_path_count, expected_api_observed; counts are plain integers 0..10000, not booleans. Native row fields exactly property, registered_on_expected_instance, value_readback_verified, target_changed_generated, target_changed_imported, unrelated_unchanged_generated, unrelated_unchanged_imported; all observations are booleans. Missing whole envelope or property row is incomplete. Malformed row, missing/extra field, duplicate/unknown property, mismatched source/run/version or contradictory positive readback without registration or expected API without geometry path is rejected.

Positive static evidence requires one declaration, positive same-class and geometry-path counts, expected API observed. All native flags and both run flags must be true; explicit negatives remain unverified with fixed reasons. Negative unrelated flags mean changed OR unverified (not proof of change). Overall verification is false unless both complete sets and run flags pass. No arbitrary exception/path/log data in the report. All safety flags stay false even on positive consistency.

Parent must bind B and C observations to the same actual source bytes, run token and Blender version, check source before/after and use the original seven-variant native measurement report and actual GLB hashes rather than manufacture stage flags from a marker. Mapping: sphere_radius -> CBDK_Param_Sphere (unrelated CBDK_Param_BevelCube), bevel_width -> CBDK_Param_BevelCube (unrelated CBDK_Param_Sphere). The existing measured coordinate/vertex displacement and unaffected-object controls must support generated/imported flags separately; bevel bounds alone are insufficient. B's static syntax and diagnosis remain separate from actual runtime registration. This reducer checks normalized flags/identity, not raw meshes or causal attribution, and cannot authenticate arbitrary supplied observations. A owns raw measurement linkage, actual B/C integration and shared CI.
