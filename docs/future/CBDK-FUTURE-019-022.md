## 将来の実装パッケージ（v0.19〜v0.22）

以下のIDは**次期計画内部の候補ID**であり、現行の`STATE.json`の要件・`NEXT`タスクではない。独立JSONの`active=false`を保つ間は実装対象に繰り入れない。着手時にはGitHubの最新実装と重複を照合し、必要に応じて分割・統合・受け入れ条件を更新する。

### v0.19 — 形状解析の実用範囲拡張

- **F019-01 / 安全な大規模比較:** 512面上限を無制限解除せず、三角形数・実行時間・メモリの予算を設けて段階的に拡張する。予算超は計測不能/部分計測として明示し、成功を偽装しない。BVH再利用・分割・キャッシュを比較実測する。
- **F019-02 / 部品対応候補:** 位置・寸法・重心・表面特徴を組み合わせ、名前変更/並べ替え・左右対称・重複部品・欠落部品で候補の曖昧さを明示する。面数だけで同一部品と断定しない。
- **F019-03 / 精度・難例の監査:** 異なる三角分割、穴・薄壁・隠れた空洞・複雑な遮蔽の合成fixtureで、検出率・誤検出・未検出領域を記録。私有実モデルは明示許可後のローカル環境のみで検証する。
- **フェーズ判定:** 合成ベースラインに対する性能・精度の変化、処理上限、安全なスキップ、未保証範囲をCI実測付きで文書化する。実モデルを使えない場合はその検証項目を未完了と記録する。

### v0.20 — アドオン生成の実用化

- **F020-01 / 宣言的UI定義:** パネル、プロパティ、オペレーターを許可済みスキーマから組み立て、値型・ID重複・依存・Blender APIバージョンの不一致を生成前に検出する。
- **F020-02 / 許可済み機能の組み立て:** 既存の部品/レシピ台帳に基づき、複数機能の登録・依存順序・無効化を安定させる。未承認部品を自動で許可リストに登録しない。
- **F020-03 / 実行検証と配布準備:** CBDK自作サンプルを対象Blender 3版で生成→登録→動作→無効化まで検証。Undo・GUI操作の自動検証範囲と人手確認を分け、Extensions形式は適合性を準備するが正式配布は別承認とする。
- **フェーズ判定:** 複数機能を持つ安全な生成アドオンが対象版のBlenderで起動・基本操作・無効化でき、失敗時の原因をレポートできる。

### v0.21 — 修正候補と改善実験

- **F021-01 / 診断と設定の照合:** ASTの構文ヒント、Blender登録状態、実際の形状への効果を区別し、候補の根拠・不確実性を一覧化する。
- **F021-02 / 制限付き修正実験:** CBDK管理の許可済み自作サンプルで、対象箇所を限定した変更候補・元データ不変・差分・復元手順・比較を検証する。実ユーザーアドオンは無断実行/変更しない。
- **F021-03 / 候補比較と採否レビュー:** 複数試行の成功/失敗/悪化/不確定を条件と測定元付きで照合し、既に良好な部品への退行も検査する。自動採用やmainへの自動マージはしない。
- **フェーズ判定:** 自作合成アドオンに対して、問題発見→候補作成→許可済み環境で再生成→差分比較→人間レビューを再現可能にする。

### v0.22 — 統合UIと利用者向け仕上げ

- **F022-01 / Blender統合パネル:** 部品・レシピ選択、生成、テスト結果、エラーの表示、途中中断・明示的再実行までを一貫して操作できるUIを作る。
- **F022-02 / 形状差分の操作体験:** 参考/生成GLBの並列表示、問題領域への移動、修正候補の人間による確認を実装。GUI Ctrl+Z/Redoと操作感は実機確認まで未検証と明記する。
- **F022-03 / パッケージと利用説明:** 互換性・依存関係・ライセンスのレビュー項目、インストール/アンインストール手順、使用例、障害時の回復方法を整理する。配布・正式公開・直接GitHub更新機能は別途承認が必要。
- **フェーズ判定:** Blender上で機能選択→生成→検証→形状比較→改善候補確認を行える。ヘッドレス検証とWindows GUI実機確認を混同しない。
