# GLB-020：匿名メッシュの境界エッジ観測（第6段階・開発中）

正式リリースは引き続き **v0.17.0**。この実装は **v0.18 ドラフトPR #25** 内のレビュー補助機能であり、実ユーザーGLBの完全な穴・内壁・体積検証を提供するものではない。

## 何を調べる？

従来の表面距離24+24点のサンプリングでは、小さな開口、欠損キャップ、内部形状の不一致が見逃される可能性がある。今回、**三角形の辺が何枚の面に共有されるか**を各匿名メッシュ部品内で調べる補助的な方法を追加する。

- **1枚だけに接する辺（境界エッジ）**：観測された開放境界の可能性を示す。
- **2枚に接する辺**：通常の接続辺として集計。ただし正しい向きや内部空洞の存在を保証しない。
- **3枚以上が共有する辺**：非多様体エッジの疑いとして集計。
- 世界座標の頂点は、シーンのAABB対角線の `1e-7` と最小 `1e-9` の許容差を使って**座標ベースで近接統合**し、エッジ出現回数を概算する。

計測は自作 `cbdk/glb_boundary_audit.py` で行う。最大 **512三角面・64匿名メッシュ部品** の既存の安全上限を維持する。

## GLB-020への統合

- `glb-diff-visualize` の `review.json` に `boundary_edge_audit` を追加。参照と生成モデルそれぞれの匿名部品で、境界エッジ数・共有辺数・非多様体候補数・近接統合で潰れた三角面数を**集計のみ**記録する。元の頂点・部品名・パスはJSONに書かない。
- ローカル `compare_viewer.html` の部品セレクターに境界エッジ数を表示する。HTMLは既存と同様、派生の私有3D座標を含むため、**元データと一緒にローカル保存**する。
- 対応候補の推定では、**空間的には似ていても境界エッジの有無や非多様体の観測が食い違う場合、単独の対応候補を「suggested」扱いにせず「ambiguous」に降格する**。見た目だけで部品の同一性を確定しない。
- 入力GLBやアドオンコードは実行・変更せず、ユーザーの私有データをGitHubやNotionにアップロードしない。

## 絶対に断定しないこと

- `boundary_edges == 0` は、**正しい閉曲面・穴がない・空洞がない**ことの証明ではない。
- 3本の境界エッジが観測されても、実際に設計上の不具合があることの証明にはならない。意図的な開放メッシュもあり得る。
- 近接頂点の統合は**浮動小数点の尺度に依存した近似**。細い隙間を融合してしまう場合も、頂点がわずかにずれて連続面を切れ目と見なす場合もある。
- エッジ境界の計数は、モデルの穴・空洞の3D位置を完全に示すものではない。別メッシュ間の辺対応も前提にしない。
- 参照と生成の同番号の部品は、同一部品である保証がない。修正すべきアドオンパラメータの原因同定もできない。

## 検証の設計

Python単体テストでは、4面の**閉じた四面体は境界エッジ0本**、1面を取り除いた四面体は**3本**、重複エッジの3面共有は非多様体候補と判定することを確認する。

Blender 4.4.3/4.5.15/5.2.1のCIではCBDK自作の四面体を実GLBとして書き出してから再読込し、参照側0本/生成側3本・対応候補を曖昧と判定できることを検証する。Chromium CIでは部品セレクター内の境界エッジ数表示をチェックする。**CIの実際の結果と実行SHAは成功を確認した後で記録する。**

次の改善候補は、ローカルのみに残る線分座標を使った**観測境界の位置表示**、複雑な隙間の誤検出対策、開いたメッシュの意図的な構造と実際の設計ミスの区別。

## GLB-020 第7段階：境界線のローカル3D位置表示（開発版）

従来の匿名部品別の境界エッジ**本数**に加えて、`compare_viewer.html` の左右3Dキャンバス上に**水色の境界線**を重ねて表示する。ヘッダーの「観測された境界線を表示」チェックでオン/オフでき、左右独立の部品選択にも追従する。移動・回転・ズームは既存の同期カメラを使用。

- `cbdk/glb_boundary_audit.py`の`local_boundary_segments`は、既存の`boundary_audit`と同じ世界座標の近接統合許容差で、**1枚だけの三角面に接するエッジ**の座標をローカルHTML専用に再構築する。面の順序に依存しない安定した並びで1部品あたり上限付きで出す。
- `cbdk/glb_diff_viewer.py`は`boundary_overlay.reference/candidate`に匿名部品番号と両端のワールド座標を含める。**この値は非公開の3D形状データである**。集計`review.json`に線分座標、元の部品名・元ファイルのパス・個別エッジIDを保存しない。
- 描画は**Canvas 2Dの簡易的な3D投影とX-ray的な輪郭の重ね描き**。奥にある境界線でも前面に出る場合があり、正確な遮蔽表示ではない。線そのものも近接統合の誤差で実際の境界からわずかにずれる可能性がある。
- **水色の線＝近接座標をまとめた結果の「観測境界」**。欠陥・穴の位置の証明ではない。開口部が設計どおりの場合もあり、線がないから完全に閉じているとも言えない。
- 過去の`boundary_edge_audit`件数と同じエッジ集合を使い、匿名部品ごとの線分数が整合しなければローカルHTMLの生成を拒否する。入力の最大512面・64部品、元GLB不変、外部通信禁止を維持。
