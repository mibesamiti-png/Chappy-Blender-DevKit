# GLB-022 第5段階 — 測定結果で次の候補値を変える合成適応探索

## 範囲と意図

今回の探索は **CBDK自身が生成した3部品（ソケット・軸・ボール）の合成モデルだけ** を扱う。既存の等間隔格子探索と異なり、GLB-020で実際に測定した差分の結果によって、**次に試すソケット開口径を変える**。

実ユーザーのアドオンや非公開GLBを自動実行・編集しない。ソケット直径はテスト用の「入力座標単位」の数字であり、現実のジョイントの寸法推奨ではない。正式v0.17.0維持、v0.18はドラフトPR #25。

## 安全に固定した探索条件

- 合成で不具合を模した下限：**0.78**。上限：合成の既知正常な参照寸法 **1.70**。
- **0.01刻み**の2桁小数で、下限を超え上限以下の値だけ許可。
- **最大4試行**。実際のGLB生成・比較の都度、観測差分から次の値を計算。
- 目標はCBDKの実験専用の **モデル全体の双方向サンプリング最大距離 ≤ 0.12**。この0.12は製造・印刷公差でも、実モデルの許容値でもない。
- 下限と上限の整数センチ値から中点を切り捨てで算出。`score ≤ 0.12`なら上限を中点へ、目標未達なら下限を中点へ。測定結果によって次の中点が変わる。
- 他部品の黄赤面数が増加したら**異常として失敗扱い**。別部品が悪化したまま最適値探しを続けない。
- スコアが下がった場合には「観測上の改善候補」として記録するが、**目標を満たした候補だけを『目標内』**として別管理。既知正常上限を自動的に測定済みの合格候補とは見なさない。
- 上限と下限の差が0.01以下、または試行数上限で停止。目標内候補が実測できなければ『未確認』として終了し、成功を偽装しない。

## 例：測定結果に応じた次の値

初期区間 `[0.78, 1.70]`から中点`1.24`を試す。合成ソケットのサンプル距離が0.12より大きければ区間を`[1.24, 1.70]`に更新して次は`1.47`。もし1.24で目標達成したなら反対方向の`[0.78, 1.24]`に切り替わり、次は`1.01`を試す。**次候補は予め固定された配列ではなく、前回の実測に依存**する。

この実験は、既知正常な上限1.70から最も小さい開口径を探すことを狙う**合成試験専用の二分探索**。連続関数の単調性や実アドオンでの因果を一般的に証明するものではない。観測最大距離が合成モデル内で滑らかに変化する前提も、一般のメッシュには外挿しない。

## コード・検証とプライバシー

- `cbdk/glb_synthetic_adaptive.py`：安全な区間・動的な中点・採否・目標内判定・最大試行数・匿名の履歴検査。
- `scripts/blender_make_glb_joint_mvp_fixtures.py`：`--single adaptive_candidate --socket-diameter N`を追加。ただし0.79〜1.70、厳密2桁小数の合成値だけ受け付ける。実ユーザーの任意設定値APIではない。
- `scripts/run_glb022_synthetic_adaptive.py`：CBDKの生成スクリプトのみをBlender `--factory-startup --disable-autoexec` で動かし、**毎回新規GLB→GLB-020比較→次候補を計算**する。試行中と終了時の合成生成器・元GLB SHA-256一致を確認。
- `tests/test_glb_synthetic_adaptive.py`：測定結果によって1.24の次が1.47にも1.01にもなるテスト、試行予算1〜4、誤った試験順序・別部品悪化・不正数値・履歴偽装・上書き拒否。
- `reports/ci/glb022_adaptive/synthetic_adaptive_history.json` と `.md` をローカルに新規保存。履歴は**匿名の数値・試行ID・目標・停止理由のみ**。GLBの座標、私有アドオンソース、元ユーザーGLBはGitHub/Notionへ送らない。
- CIはBlender 4.4.3/4.5.15/5.2.1で実GLB再生成と履歴検証を行い、従来の `basic`/`cross_part`/`progressive`/`generated_grid` を維持する。

**未解決：** この段階では固定範囲・固定目標・最大4回の合成実験のみ。値を実ユーザーアドオンへ反映する機能、他形状での単調性、実物の公差、厳密Hausdorff距離や形状内部の完全一致は未対応。GLB-022は `partial` のまま。

検証成功のコードSHAとCI run IDは、実際に成功確認してから追記する。
