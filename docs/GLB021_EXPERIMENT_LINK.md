# GLB-021：測定元に結び付いたAST候補・合成反復レビュー

既存NEXT-019の「合成変更履歴と許可済み反復の接続」と、NEXT-009の安全な設定照合を進める。新しいロードマップ項目を追加するものではない。

## 解決する問題

AST候補のレビューと合成反復の実験履歴は従来別ファイルだった。今回、GLB-022が測定した**初期GLB-020集計JSONの正規化SHA-256**を実験条件に記録し、同じ測定元であることを確認してから、明示ソースをASTのみで読む。

GLB-020の三角面/候補分類を再計算・変更しない。自動部品認識、実アドオンの実行、修正値の推測/適用、コード採用は行わない。

## 利用方法

新しいランナーが出力した初期集計と実行レビューを使用する。旧記録は従来CLIで読めるが、測定元SHAを持たない記録はこの連携には使用しない。再生成は利用者が既存の合成ランナーを明示実行するときだけ。

```bash
python -m cbdk.glb_visual_experiment_review --visual-review reports/ci/my_run/review_narrow/review.json --run-review reports/ci/my_run/synthetic_run_review.json --source /local/path/to/addon.py --role part_003=socket --output reports/latest/my_linked_review.json
```

JSONと同名Markdownの2ファイルをignored `reports/latest`へ**新規作成のみ**で出力する。候補名・匿名ソースラベル・クラス/行を含むため非公開。元ソース本文、既定値、私有ファイル名/パス、生座標は含めず、標準出力は匿名の件数のみ。GitHub/Notionや公開CI artifactへ実ユーザーの生成レビューをアップロードしない。

## 結び付けの条件と意味

1. GLB-020集計が既存の厳格検査と固定3部品の合成条件を通ること。
2. 実験の安全フラグ/経路/採否を既存の実行レビュー検査で確認し、入力整合性がverifiedで、初期集計SHA・距離・面数・スケールが一致すること。不一致は私有Pythonの読取前に拒否する。
3. 候補ソースは既存のAST宣言/参照/形状フロー解析のみ。ソースをimport/execしない。
4. 人が`part_003=socket`を指定し、`socket_opening_diameter`宣言が完全一致した場合だけ、合成生成器の`socket_diameter`操作への**人手確認用の名称対応候補**を表示する。他の設定名や役割は未対応のまま。
5. これはAST候補が実際に生成器を制御した証明ではない。参照先インスタンス、実際の登録、実プロパティ効果、真の部品同一性は未確認。SHA一致も証拠の真正性を認証しない。
6. 完了・未完了・失敗の検証済みprefixを実状態のまま併記する。試行0や失敗を修正成功として扱わず、入力改変/未確認状態は連携自体を拒否する。合成試験値は実ユーザー設定の推奨値ではない。

`baseline_review_sha256`は既存conditions schemaに追加した省略可能フィールド。旧schema1/2条件・実行レビューの読取や、従来の成功履歴形式は維持する。新しいランナーは必ずこの結び付けを記録する。

## 検証と完了範囲

Pythonでは元ソース非実行/非改変、異なる測定元の事前拒否、旧記録、失敗/試行0、不正な因果・安全フラグ、候補/宣言位置の偽装、既存ファイル/パス逸脱、標準出力への私有情報漏出を検証する。

Blender3版CIは既存の自作合成実験を再利用し、`scripts/verify_glb021_experiment_link.py`で完了・未完了・制御された模擬タイムアウトのレビューを生成する。別候補の集計を初期測定元として使うと拒否することと、元ソース/測定JSONのSHA不変を確認。私有シートはreports/latestに置き、アップロード対象reports/ciへ入れない。新しい任意アドオン実行や追加GLB実験は不要。

NEXT-019はこの接続の受け入れ条件を対象CIで確認後に完了判定する。NEXT-009の自動化部分は拡充するが、実ユーザーの設定実体・登録・因果の確認を完了とはしない。GLB-021全体partialを維持する。実測SHA/CIは成功確認後にSTATE/HANDOFF・PROGRESSへ記録。
