# GLB-022 第4段階：制限付きの合成候補値を自動生成して比較

## 開発範囲

CBDK自作のソケット・ボール・軸の3部品に限り、ソケット開口径の候補値を**コードで算出**してからBlenderで実際にGLBを新規生成し、GLB-020の匿名・集計差分で比較する。これはGLB-022の段階的な実験であり、実ユーザーのアドオン、私有GLB、任意のPythonコードを実行・修正する仕組みではない。正式版v0.17.0は維持、v0.18はドラフトPR #25。

## 算術的な候補値

テスト用の**固定範囲**は直径 `0.78`（意図的な不具合）から`1.70`（CBDKの既知正常値）まで。入力の上下限は利用者から受け取らない。

```text
初期: 0.78
差分: (1.70 − 0.78) ÷ 4 = 0.23
試行1: 1.01
試行2: 1.24
試行3: 1.47
試行4: 1.70
```

これまでは`narrow_mid`や`identical`といった固定の試験IDを直接列挙していた。今回の`cbdk/glb_synthetic_grid.py`は、固定の整数センチ単位範囲を4分割し、**数値の候補を実際に算出**する。候補は最大4、範囲外・小数桁違い・未知IDは拒否する。

`scripts/blender_make_glb_joint_mvp_fixtures.py`に、`--single grid_candidate --socket-diameter 1.01`のような専用の合成試験モードを追加。これも算出した**4種類の値だけ**を受け付け、任意の数値入力APIにしない。

## 採用・棄却と停止

- GLBをBlenderで毎試行新規生成し、同じ参照GLBと比較。GLB-020の`reference_sampled_max`・`candidate_sampled_max`の**双方向最大サンプリング距離**を評価する。
- **観測最大距離が厳密に減り、かつソケット・ボール・軸で観測される分類悪化がない**場合のみ、その候補を採用する。改善が止まれば棄却し、採用済みの状態を維持する。
- 1/2/3試行で予算を打ち切った場合は、**未修復の状態を正直に記録**する。最大4試行、または観測差分0の条件で停止。最後の1.70はあらかじめCBDKが持つ正常な合成形状であり、新しい実ジョイントの最適寸法を発見した意味ではない。
- 正常なソケット以外にボール・軸の位置や形状の観測悪化が発生した場合は拒否。従来の`cross_part`と`progressive`の別部品の悪化テストも維持する。
- 入力は集計JSONのみ。差分0は**全形状の厳密な一致、細穴や内壁の確認、部品の真の同一性を保証しない**。

## 品質とプライバシー

`scripts/run_glb022_synthetic_grid.py`は**CBDK自身が持つ生成スクリプトだけ**を、CI上で明示した信頼済みBlenderで起動。公開・プライベートな別アドオンは実行しない。出力先はリポジトリの`reports/ci/<新規ディレクトリ>`のみ。生成器・作成した各GLBのSHA-256を処理前後で比較し、元のデータを変更しない。

`synthetic_grid_history.json`・`synthetic_grid_history.md`には算出した合成値・観測最大距離・採否・停止理由のみを記録。ローカル新規保存に限定し、既存ファイルの上書きや私有ソース/形状の公開を拒否する。

`tests/test_glb_synthetic_grid.py`で固定数値の計算、候補の改善停止による棄却、打切り予算、他部品悪化時の拒否、不正JSON・虚偽の安全フラグ・履歴上書きの禁止を確認する。Blender 4.4.3 / 4.5.15 / 5.2.1 のCIでは、従来の`basic`・`cross_part`・`progressive`に加え、4候補の生成→比較を新規に実行する。

**今回のCI対象コミットSHAと検証結果は、実際のテストが完了してから記録する。** GLB-022全体の状態は`partial`を維持する。

## 未実装

この候補生成は**4分割の固定格子探索**であり、結果を使って次の候補値の生成規則を変える適応的最適化ではない。また、実ユーザーアドオンの操作、実際の印刷部品の機械公差評価、部品ごとの厳密な幾何誤差計算、任意の連続値の探索は未対応。次の開発では、固定格子で安全性とテストを確認したあと、許可済み合成モデルの範囲内で実測に応じた探索順や打ち切りの変更を検証する。
