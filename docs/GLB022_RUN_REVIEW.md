# GLB-022 第6段階：合成反復の失敗・打切り・人手レビュー

## 解決する問題と範囲

これまで適応型探索は正常終了時だけ履歴を保存し、生成・比較・安全検査で失敗すると測定済みの経過が最終レポートに残らなかった。今回は既存のCBDK自作合成モデル・0.78〜1.70・0.01刻み・最大4試行を維持し、途中経過と失敗理由をローカルに残す。

ユーザーのアドオンや私有GLBは読み込まない。任意コードの実行、値の自動採用、探索範囲の拡大、自動再試行・再開、公開・マージは追加しない。GLB-022全体はpartial。

## 実行と確認

既存コマンドの利用方法・正常終了の履歴は維持する。出力先は毎回新しい`reports/ci`直下のフォルダのみ。

```bash
python scripts/run_glb022_synthetic_adaptive.py --blender /path/to/blender --output reports/ci/my_synthetic_run --budget 4
python -m cbdk.glb_synthetic_run_review reports/ci/my_synthetic_run/synthetic_run_review.json
```

- `checkpoint_000.json/.md`から連番で、工程開始前と検証済み履歴を**新規作成のみ**で保存する。最大16組。通常4試行では14組。プロセスが強制終了して最終レポートが無い場合は、最後の有効なチェックポイントJSONを上の読取コマンドで指定する。
- `synthetic_run_review.json/.md`は処理を完了・失敗として終了するときのレビュー。`synthetic_adaptive_history.json/.md`は従来どおり正常な予算完了時に作成する。従来履歴があっても最終レビューが失敗なら全処理の成功を意味しない。
- 読取CLIはJSONのスキーマ・採否・探索経路・安全フラグを再検査して日本語を表示するのみ。Blender起動・ソース実行・自動再開は行わない。
- JSONが有効な成功受領として先に残らないよう、Markdownを書いた後にJSONを作成する。既存ファイル・シンボリックリンクを上書きしない。

## 状態と意味

| 状態・項目 | 意味 |
|---|---|
| `incomplete` | 実行中または未完了。プロセスの稼働・正常終了を証明しない |
| `failed` | その工程で停止。固定の失敗コードと検証済みの履歴だけを残す |
| `completed` | 要求した試行予算の処理・入力整合性・履歴出力・最終記録まで完了。目標達成とは別 |
| `validated_attempts` | 安全検査と経路再検証を通過した候補の数。失敗候補を数に含めない |
| `unvalidated_attempts` | 予算から検証済み試行を引いた枠数。処理中/失敗候補も含むため、再試行できる回数ではない |
| `sampled_goal_observed` | 既存の合成目標内候補が観測されたか。実行完了・最適値・完全一致ではない |
| `input_integrity` | 記録時の生成器・把握済み生成GLBのSHA-256照合。`failed`なら観測を採用しない |

失敗候補のスコアは検証済み履歴に追加しない。以前の目標内候補が残っていても失敗を成功へ変更しない。座標系変更・他部品の悪化・不正な測定は停止し、直前の観測経路を保持する。

## 失敗分類と人手の確認

| コード | 確認内容 |
|---|---|
| `generation_failed` / `generation_timeout` | 合成生成器の環境・終了状態・起動負荷 |
| `comparison_failed` / `comparison_timeout` | ローカル比較出力・比較処理の負荷。未測定候補を採用しない |
| `invalid_measurement` | 測定JSONの安全フラグ・面数・有限数値・経路 |
| `cross_part_regression` | 非対象部品の観測悪化。候補を履歴へ採用しない |
| `coordinate_scale_changed` | 共通座標スケールの不一致 |
| `input_integrity_changed` | 入力・生成器変更。記録済みの観測も採用せず隔離 |
| `io_failure` / `interrupted` / `unexpected_error` | 出力容量/権限・中断・未分類の失敗。完了扱いしない |

例外の自由文、コマンド全文、私有パス、ユーザーの設定名、元ソース・生座標を診断へ転記しない。CLI失敗は非ゼロ終了（通常1、中断130）と固定文だけ。保存自体が失敗した場合は有効な以前のチェックポイントを残し、最終レビュー保存失敗として終了する。

## 検証と限界

- Python：正常4試行/短予算、ゼロ試行のチェックポイント、途中比較/生成タイムアウト、他部品悪化、スケール変更、不正測定、入力改変、出力失敗、中断、偽完了/安全フラグ型、JSON異常、非上書き、非実行の読取を検査する。
- 既存のBlender3版CIで通常4試行の実生成・比較を継続し、レビューと全14チェックポイントを検査する。
- `scripts/verify_glb022_failure_review.py`は**合成GLB生成・基準比較を実Blenderで行った後、候補比較のタイムアウトだけを模擬注入**する。失敗終了、候補未採用、基準履歴保存を確認する。自然発生のハングを再現した試験とは記録しない。
- OSの強制終了・電源断・ディスク書込み障害に対するトランザクションや完全保存は保証しない。両ファイルの完全な原子的作成、記録の真正性、自動再開は対象外。
- 合成目標0.12、全体サンプリング距離、部品候補の従来の限界を維持する。実ユーザーの因果・最適値・GUI操作・全形状一致は未検証。

CI結果・対象コードSHAは実測を確認してSTATE/HANDOFFとPROGRESSへ記録する。Notionはそれらの公開可能な状態のみを同期し、生成チェックポイントそのものはアップロードしない。
