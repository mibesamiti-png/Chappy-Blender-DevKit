# NEXT-023：同条件の複数合成実験の比較レビュー

## 受け入れ範囲

現行ロードマップNEXT-023/NEXT-020を実装する。CBDK自作合成モデルの実行レビュー2〜16件を**読取専用**で比較し、同条件で観測された改善・悪化・差なし・指標混在を日本語で表示する。失敗・未完了・入力改変・条件不一致を成功比較から除外する。

GLB-021/022全体を完了扱いにしない。私有アドオンや任意モデルを実行・変更せず、自動採用・最適値推薦・再試行・再開も追加しない。GLB-020のMVP追加機能凍結を維持する。

## 利用方法

既存の適応探索を同じ条件で別の新規フォルダへ実行し、最終レビューを比較する。

```bash
python -m cbdk.glb_synthetic_run_compare --run reports/ci/run_a/synthetic_run_review.json --run reports/ci/run_b/synthetic_run_review.json --output reports/latest/my_run_comparison
```

出力はignored `reports/latest` または `reports/ci` 直下の**新規フォルダ**に限定し、`synthetic_run_comparison.json/.md`を新規作成する。JSONは検証済み実行証拠の匿名スナップショットを含む。元パス・任意ラベル・私有ソース・GLB座標は出力しない。不正レポートの本文も保存しない。生成レポート自体をNotionへ同期しない。

CLIはBlenderもソースも実行しない。比較可能な実行が2件以上なら終了コード0、それ未満でも除外理由を保存して2を返す。これは処理の成否であり、形状の合格コードではない。読取不能・不正JSONは匿名の`invalid_report`として除外。上限外や危険な出力先は拒否する。

## 実験条件の証拠と互換性

既存の実行レビューschema 1はそのまま読み取れるが、条件の証拠がないので比較には使わない。新しい適応ランナーは基準測定後にschema 2を出力する。基準測定前の記録はschema 1のまま。既存の適応成功履歴JSONの形式と試行条件は変更しない。

schema 2の`conditions`には次を保存する。

- 固定プロトコル、合成の座標単位、範囲0.78〜1.70、目標0.12、最大4試行、24点/面、512面上限と指標ID。
- 明示的に列挙したCBDK生成器・ランナー・比較/検証ソースのSHA-256集約。任意のPythonファイルをインポート・実行しない。
- 基準GLBと初期欠陥GLBのSHA-256、宣言されたBlenderバージョン、共通AABB対角線、初期距離と異常面数。

候補計測のBlender版も基準版と一致させる。既存の入力GLB/生成器に加え、列挙した比較/検証コードの変更も試行中に検知して停止する。条件の初期観測は履歴の初期観測と一致しなければならない。

条件は実行レビュー側の自己申告を含む。SHAは変更検出であり、真正性・権利・実行環境全体の同一性を認証しない。同じ形状でもGLBのバイト列が違えば安全側で条件不一致となる。異なるBlender版や異なるコードSHAの結果は、このコマンドでは同条件として比較しない。

## 比較規則

最初の「完了・入力照合済み・条件付き」実行を比較基準とする。これは推奨・最良実行の自動選択ではない。

1. 正常終了、入力整合性、条件、予算を検査する。失敗前に目標内候補があっても成功比較に入れない。
2. 検証済み履歴から観測上の最良距離とソケット異常面数を再計算する。
3. 既存の距離分解能1e-6以内かつ面数差0なら「有意な観測差なし」。距離が減り面数が増えなければ「観測上の改善」、距離が増え面数が減らなければ「観測上の悪化」。それ以外は「指標が混在・人手確認」。
4. 除外実行は基準との差分を計算せず、理由だけを表示する。入力改変の経過は数値自体を比較欄へ出さない。
5. JSON/Markdownの再表示時も匿名入力スナップショットから結果を再生成し、偽の判定・安全フラグ・件数を拒否する。

サンプリング指標の比較に過ぎず、AST候補の因果・正しい設定値・全域の幾何同一性を証明しない。ASTレビューと実験的因果確認の既存の区別を維持する。

## 検証と資源観測

- Python：同条件/改善/悪化/混在/微小差、条件と予算の不一致、失敗/未完了/入力改変、旧schema、偽証拠・JSON型、2〜16件上限、ソース非実行、非上書きと非実行CLIを確認する。
- Blender3版CI：独立した通常4試行をもう1回だけ実生成し、既存の通常実行と比較する。正常2件が比較可能で差なし、明示的な模擬タイムアウトを保存した実行が対象外であることを確認する。従来の全プロトコルは維持する。
- `scripts/verify_glb023_run_comparison.py`で比較のウォームアップ後、tracemalloc有効時の3回中央値とPython割当ピークを観測する。2件は独立した実験、16件はその証拠を複製した負荷試験。16回独立実験したとは記録しない。ファイル読込・Blender実行は計測外。
- 時間・メモリに速度向上の閾値を設けず、根拠のない最適化はしない。ローカルの予算1・Blender4.3.2の証拠は対象3版CIと分離する。

実測のコードSHA・CI・性能値は成功確認後にSTATE/HANDOFF/PROGRESSへ記録する。現在ロードマップにない大規模構想や新しいNEXT番号は追加しない。
