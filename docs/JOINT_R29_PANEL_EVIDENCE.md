## A adapter (independent actual observations)

Call reduce_panel_evidence(records, run_id=..., blender_version=..., mode=..., scene_sha=..., measured=..., lifecycle=..., measured_lifecycle=...). Parent supplies fresh 32 lowercase hex run ID, exact version 4.4.3/4.5.15/5.2.1, mode stub/native and independently measured scene SHA using existing joint_preview.scene_signature. Do not derive expectations from claimed records. Normalized record and parent measured mapping (keyed by case) contain same exact fields: run_id, blender_version, fixture_id=joint_rotary_fixture_v1, mode, case, steps. This is an A adapter, not a requirement to change B/C raw schemas. Each case is an independently prepared fixed scenario on the same preserved scene; never invent observations to fit a scenario. Case order and step order:

- adopt_restore: START (IDLE to RUNNING, RUNNING_MODAL), COMPLETE (native iterator reaches READY), ADOPT (selected declared_target, 5 to 4, ADOPTED_DIMENSION_ONLY), RESTORE (4 to 5, RESTORED).
- rejected_candidate: ADOPT direct negative control with fresh selected rejected row; CANCELLED and FAILED/READY, unchanged 5.
- stale_candidate: ADOPT direct negative control with noncurrent READY; CANCELLED and FAILED/READY, unchanged 5.
- cancel_retry: START, ADOPT and RESTORE direct busy refusals, CANCEL (request only), INTERRUPT (later controlled boundary CANCELLED), RETRY (existing synchronous action to READY). No automatic adoption.
- failed_retry: START, FAIL (controlled failure boundary), RETRY (explicit synchronous retry to READY).
- blocked: direct START/CANCEL/RETRY/REJECT/ADOPT/RESTORE negative controls; all CANCELLED, BLOCKED sticky, no change.
- explicit_reject: fresh READY, REJECT, REJECTED, unchanged diameter.

Each step has index (0-based plain int), action, operator (START=cbdk_a.joint_start; CANCEL/RETRY/REJECT=cbdk_a.joint_action; ADOPT/RESTORE=cbdk_a.joint_dimension; COMPLETE/INTERRUPT/FAIL=null), method, explicit (true only explicit action/probe), result (FINISHED/CANCELLED/RUNNING_MODAL), before, after, view_before, view_after. Capture real operator returns, not a marker. For native mode use native_operator for actual direct native operator calls; START may be a distinctly labeled callback_simulation with real RNA when controlled modal invocation is required. COMPLETE requires native_iterator executing actual native work; interruption/failure may be native_iterator or callback_simulation and must be labeled. Callback simulation is not GUI or direct native operator input. Stub mode requires stub throughout. No production-panel click, Windows GUI or native Undo/Redo inference. Within each case successive snapshots and projections must agree at the boundary; selection/scene preparation happens before the case or is observed as part of the actual fixed operation, not fabricated.

Snapshot fields: status, reason (fixed known code or empty, never raw paths/free exceptions), diameter, target=4, policy=FREE, fresh (actual current candidate/RUNS and input identity match, not JSON status alone), selected (zero-based row or null), candidates (ordered fixed prefix max 3), scene_sha, cancel_requested. Each row: candidate_id, diameter, decision, score, accepted_for_review. Fixed IDs and expected outer diameters from existing proposals(5,4,FREE), accepted iff existing decision observed_improvement/target_reached. Finite bounded values, exact order, no arbitrary candidate, unknown states/reasons/decisions or forged approval. Fresh READY requires complete fixed native decision sequence regression/observed_improvement/target_reached; the selected negative row may still be fresh but not adoptable. No re-evaluation of candidate geometry in D; parent captures existing measurements/review independently.

View fields: fixture_id, part_ids=[rotary_outer,rotary_axle], recipe_id=fixed_rotary_fixture (normalized fixed recipe role, not catalog ID), status, reason, available, candidates, selected, enabled_actions (unique fixed action IDs). Normalize actual B projection and C drawn enabled controls, not expected flags. Available rows match the actual snapshot; unavailable has no candidate rows/selection. Stale READY unavailable and no ADOPT; fresh READY must show candidates, and only a selected fresh accepted row may expose ADOPT. RUNNING only CANCEL, BLOCKED none. Failure/cancellation/rejection/no-candidate require explicit RETRY; adopted dimension requires RESTORE. Other supported safe controls can be present within existing guards; UI enablement does not grant authority. Parent records actual existing operator refusal even when UI control is hidden/disabled, as a negative probe. No duplicate undo push.

Lifecycle (both claimed and separately measured): common identity plus registered, duplicate_rejected, unregistered, existing_registration_unchanged, scene_before, scene_after, fixture_settings (axis Z, origin [0,0,0], unit_scale 1, axle_diameter 2, clearance .4, mode OBJECT), draw_method (native_panel_draw_recording_layout or stub), projection_source (real_projection or stub). Actual Blender Panel.draw with recording layout is not a GUI click. All lifecycle flags must be true, every scene signature equals independently measured protected scene SHA; only explicit ADOPT/RESTORE may change panel's own diameter. Native requires actual B projection, actual native draw boundary and separately captured parent observations; test stub may verify only stub contract. Provider hashes/configure and actual generation remain existing A/C operations; no provider execution in D.

Missing observations are incomplete; malformed/duplicate/out-of-order/unknown/incorrect identities, stale adoption, scene/measurement/restore mismatch or forbidden claim are rejected. Fixed reason codes only. All safety flags remain false even with complete normalized native observations; consistency is not authenticity, authority, general geometry verification, automatic adoption, mesh commit or distribution.
